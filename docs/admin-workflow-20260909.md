# 상품·판매관리 업무 흐름 개편

기준: main b05426544d896835f39717a7ccd9e688283451cc. 운영 배포 전 검토본.

## 상품 관리

- 판매 준비 / 판매 중 / 판매 종료 탭. 시작·종료 시각과 재고로 계산하며 수동 판매 중지를 자동 해제하지 않는다.
- 검색, 상품 분류, 상시/공동구매, 비전시 링크 상태는 보조 필터.
- 상품 등록 4단계: 기본 정보 → 가격·옵션 → 판매 설정 → 배송·최종 확인. 단계 이동 시 입력 상태 유지.
- 판매 방식(상시/공동구매)과 운영 상태(준비/허용/중지)를 별도로 저장. 새 상품은 판매 준비가 기본값이며 확인 후 판매 허용을 선택한다.
- 기존 상품 코드 복제 유지. 상품명에 대응하는 기존 분류를 제안하고 관리자가 선택한다.
- 배송 기본값은 사이트별 브라우저 저장소에 저장하며 다음 신규 등록에 적용. 다른 브라우저·기기로 공유되지 않는다.
- 공급사와 출고 예정일을 상품에 저장. 출고일은 시간대 변환 없이 날짜 문자열로 전달.

## 판매 관리와 발주

- 신규 확인 / 발주 대기 / 고객 요청으로 분리. 전체 이력과 상세 필터는 별도 진입.
- 결제 확인, 수령인, 연락처, 배송지, 상품·수량, 진행 중 환불 여부로 자동 분류. 주문 상태를 자동 변경하지 않는다.
- 발주 확정 시 서버가 선택 주문을 잠그고 다시 검사. 하나라도 부적합하면 전체 롤백.
- 확정 이력과 당시 주문 내용을 한 트랜잭션에 저장하고 배송준비로 전환한 다음 엑셀을 제공.
- 동일 요청 재시도는 기존 이력을 반환. 이미 발주된 주문을 새 요청으로 재확정하지 않는다.
- 결제 단계에서 확보한 재고는 발주에서 다시 차감하지 않는다.
- 공급사·출고일로 파일 행을 정렬. 미지정 값은 미지정으로 표시. 공급사로 실제 파일을 보내는 기능은 포함하지 않는다.
- 확정 파일 재다운로드는 저장된 내용을 사용. 일반 주문 목록 다운로드는 주문 상태를 변경하지 않는다.
- 기존에 열린 구버전 화면의 dispatch 요청은 409로 차단해 새 확인 절차로 안내한다.

## 상품 분류

- 숨기기는 신규 선택에서만 제외하며 기존 상품은 계속 편집 가능.
- 통합은 관리자 확인 후 같은 사이트 내 상품 분류를 변경하고 이전 분류를 숨긴다. 상품 수가 변경되면 재확인 요청.
- 산지픽 농산물과 해산물 간 통합은 차단. 특정 분류의 실제 통합은 운영자가 대상 선택 후 실행한다.
- products_shop.site를 기존 분류에서 채우고 소속 변경을 DB에서 차단. 기존 공개 화면의 분류 기반 경로는 호환 유지한다.
- 보관된 상품과 과거 주문의 상품명·금액은 변경하지 않는다.

## 검증과 배포 조건

- 신규 격리 DB/도메인 검증 14개 통과: 발주 재시도, 전체 롤백, 환불 충돌, 사이트 권한, 스냅샷 재출력, 분류 통합·숨김, 반복 마이그레이션, 날짜, 항목 누락 주문 등.
- 기존 관리자 검증 73개 통과.
- 브라우저: 실제 컴포넌트에 예시 API를 연결해 단계 이동·입력값 유지·수동 판매 중지 유지·주문 분류·모바일 사유 표시 확인. 실제 주문 처리 없음.
- 전체 Next.js 빌드 확인. 운영 DB, 결제, 환불, 고객 문자, 공급사 전송 미실행.
- scripts/admin-workflow.sql은 기존 migrate-order-site.cjs 트랜잭션에 포함. 배포 시 코드 재시작 전에 적용 필요.
- CI와 기존 배포 검증에 test:admin-workflow 추가. 운영 배포는 별도 진행.
