# 방문 통계 운영

2026-10-20 진단에서 두 사이트 모두 수집 플래그, 통계 DB 연결, 해시 키가 없었습니다. 이때 수집 API는 204를 반환하므로 HTTP 성공만으로 수집 정상 여부를 판정할 수 없습니다. 기록되지 않은 과거 방문자·세션을 서버 요청 수로 대신 채우지 않습니다.

배포 시 `enable-visit-analytics.cjs --enable`이 최초 연결을 준비합니다. 기존 PostgreSQL 서버에 `blendpick_analytics` 전용 DB와 `blendpick_analytics_app` 제한 계정을 생성합니다. 주문 DB에는 통계 테이블을 만들지 않습니다. 새 비밀번호와 독립 해시 키는 서버 `.env.local`에 권한 0600으로 저장하며 출력하지 않습니다. 외부 서비스 가입이나 추가 서버가 필요하지 않습니다.

연결 설정이 이미 완성돼 있으면 키와 활성화 값을 보존합니다. 중단된 최초 설치는 `ANALYTICS_BOOTSTRAP_PENDING`과 소유 표시를 확인해 같은 키로 재개합니다. 소유를 확인할 수 없는 기존 DB·계정, 부분 설정, 권한 부족은 변경 전에 중단합니다. 기존 DB·계정을 삭제하거나 비밀번호를 교체하지 않습니다.

`prepare-visit-analytics.cjs`는 기존 테이블을 읽기 쿼리로 검증하므로 운영 계정에는 스키마 생성 권한이 필요하지 않습니다. 서버 재시작 후 `check-visit-analytics.cjs`가 양쪽 호스트의 실제 수집 API → DB 저장 → 동일 이벤트 중복 방지를 검증합니다. 검증용 임의 이벤트와 세션만 제거하며 고객 기록은 변경하지 않습니다.

90일이 지난 방문 기록은 `blendpick-visit-retention.timer`가 한국시간 매일 03:30에 정리합니다. 주문·결제·배송 테이블에는 접근하지 않습니다. 수집을 중지하더라도 보관 기간 정리는 계속됩니다.

관리자 `/admin/visits`에서 사이트별 오늘·7일·30일 방문자, 세션, 페이지 조회를 확인합니다. 관리자 로그인 방문, 식별된 봇, GPC/DNT 및 분석 거부 환경은 집계에서 제외됩니다. 수집 장애는 주문·결제 처리를 막지 않습니다. `Visit Analytics Health` 실행과 배포의 실수집 검사에서 설정 또는 저장 장애를 확인할 수 있습니다.
