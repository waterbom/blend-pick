# [보류중] 인플루언서/손익관리 개발 계획

> 상태: **보류** — 사용자가 "인플루언서 등록"이라고 말하면 재개.
> 작성일: 2026-07-12. 클라이언트 요청사항 원문 기반 분석.

## 클라이언트 요청 요약

1. **손익관리**: 공구별/상품별/인플루언서별 순이익 확인.
   - 계산식: 총매출 = 판매가×수량 / 인플루언서 수수료 = 총매출×수수료율 /
     회사 순이익 = 총매출 − 공급가 − 배송비 − PG수수료 − 기타비용 − 인플루언서 수수료 − 부가세금액
   - 필터: 기간/상품/인플루언서/사업자유형/판매채널
2. **인플루언서 관리** (관리자): 프로필/연락처/플랫폼/팔로워/카테고리/
   사업자유형(일반·간이·프리랜서)/계좌/공구목록/누적매출/누적수수료/메모
   + 첨부파일(사업자등록증·통장사본·신분증사본)
3. **인플루언서 공구현황 탭** (인플루언서 본인): 진행상품/판매기간/판매수량/총매출/
   수수료율/예상수수료/사업자유형/예상 실지급액/정산상태
   - 실지급: 일반 = 수수료 / 간이 = 수수료 − 부가세10% / 프리랜서 = 수수료 − 원천세3.3%
4. **연결 구조**: 주문 → 공급가 연결 → 인플루언서 연결 → 수수료 자동계산 →
   손익/공구현황/정산 반영

## 기존 자산 (2026-07-12 조사 결과)

- OS DB(`pool`): `influencers`, `campaigns` 테이블 존재 — 고객 화면(공구 페이지,
  InfluencerSelector, CampaignDetailClient)에서 사용 중. 필드는 최소 수준.
- Shop DB(`shopPool`): `products_shop`(공급가 없음), `orders`, `order_items`,
  `settlements`(PG수수료 카드 3.63%/이체 1.65% 자동계산, 배송완료 시 생성)
- 관리자 골격: products/orders/shipments/settlements/categories + AdminSidebar
- 업로드 API: `public/uploads` 저장이라 민감 서류엔 부적합 → 비공개 저장 + 권한 게이트 필요
- 주의: OS DB와 Shop DB는 분리되어 있어 SQL 크로스조인 불가 → 앱 레벨 조인 또는
  주문에 인플루언서 스냅샷 저장 설계 필요

## 구현 단계 (예상 4~5회 세션)

1. DB 확장 + 주문-인플루언서 연결 (공급가 컬럼, influencer_id/수수료율 스냅샷, 기타비용)
2. 인플루언서 관리 CRUD + 첨부파일(비공개 저장) + 누적 집계
3. 손익관리 페이지 (계산식 + 필터)
4. 인플루언서 로그인 체계 + 공구현황 대시보드
5. 정산 연동 + 전체 검증

## 시작 전 클라이언트 확인 필요 (미답변)

1. 수수료율 귀속: 인플루언서 고정 vs 공구(캠페인)별?
2. 부가세금액 계산 기준 (총매출의 10/110? 마진의 10%?) — 세무 확인 필수
3. 인플루언서 로그인 방식 (관리자 발급 ID/PW? 카카오? 전화번호 인증?)
4. 기타비용 입력 단위 (주문별? 공구별?)
5. 판매채널 종류 (자사몰 외 외부 채널 주문 포함 여부)
6. 공급가가 옵션별로 다른지?
