# 관리자 운영 홈 통합 · 2026-10-20

## 목적

운영 요약, 오늘 처리할 일, 방문 통계를 매번 따로 열어야 하고, 왼쪽 메뉴와 상단 탭이 중복되어 일상 업무를 파악하기 어렵다. 운영 홈에서 처리할 일과 매출·방문 현황을 함께 보여주고, 핵심 메뉴는 처음부터 이름을 표시한다.

| 기존 화면/영역 | 개편 구성 |
| --- | --- |
| 운영 요약·오늘 처리할 일·방문 통계 | 운영 홈 한 화면. 기존 `/admin/operations`, `/admin/visits?days=30` 주소는 업무/방문 위치로 연결 |
| 그룹 메뉴 → 하위 메뉴 → 반복 상단 탭 | 핵심 업무 직접 링크. 보조 기능은 `기타 관리`, 메뉴 검색도 유지 |
| 업무 유형별 큰 카드·펼침 목록 | 우선순위 업무 목록에 사유·경과시간·처리 링크 표시. 추가 항목은 같은 화면에서 더 보기 |
| 개별 매출·방문 기간 선택 | 오늘/최근 7일/최근 30일 공통 선택 |
| 배송 홍보 카드·4단계 안내 카드 | 현재 주문·배송·공구 현황으로 대체 |
| 정산 기간 탭·200건까지만 표시되는 내역 | 기간 금액 카드와 주문/구매자 검색. 환불 확인 필터, 전체 내역 50건 단위 페이지 이동. 추이는 필요할 때 펼침 |
| 서버 트래픽·자동 점검 안내 | 트래픽·자동 점검 한 화면 |
| 주문 KPI 카드·숨긴 상세 필터·상품별 펼침 목록 | 한 줄 범위 필터와 항상 보이는 검색. 처리할 주문은 한 표에서 바로 확인·선택. 최근 발주 3건도 바로 재다운로드 |
| 배송 단계마다 반복한 주문/배송 목록·별도 완료 목록 3개 | 발주는 주문관리로 연결. 배송준비·배송중 한 표, 완료 이력은 같은 표의 상태 필터. 송장 등록은 간결한 도구 줄 |
| 교환 탭·반품 탭 | 두 신청을 함께 표시하고 구분·사유·수거지·처리 버튼 제공. 취소는 출고 중지 확인 안내와 함께 표시 |
| 배송 자동조회 대형 요약·계속 노출된 실행 이력 | 마지막 실행 요약과 조회 버튼은 바로 표시. 과거 이력·주문별 로그는 필요할 때 펼침 |
| 상품별 코드/등록일 열·판매량 KPI 카드·긴 집계 안내 | 코드·분류는 상품명 아래, 판매 상태·일정은 함께 표시. 판매량 합계 한 줄과 재고 확인 필터, 집계 설명만 접기 |
| 회원 9개 열·행을 열어야 보이는 승인/계정 버튼 | 회원·구매 활동을 6개 열로 묶고 신청 승인/반려·역할·활성 상태를 바로 처리. 주문 이력만 추가로 열기 |
| 리뷰별 큰 카드·검색 없이 공개/숨김 탭 | 상품·작성자·본문을 한 줄 구성으로 묶고 검색/별점/사진 필터. 숨김도 읽을 수 있는 대비 유지 |
| 숙박 목록/재고 탭·숙소 탭·예약 상태 탭·전달 카운터 | 숙소 한 개 선택이 요약/예약/재고에 공통 적용. 미전달/확인 대기를 요약에서 바로 필터. 재고를 열어도 목록 유지 |

실제 메뉴 사용 빈도 기록은 없으므로 사용률을 추정하지 않는다. 거래·처리 기능 자체를 삭제하지 않고 중복 탐색과 안내 영역을 정리했다. 산지픽에는 숙박 메뉴가 표시되지 않는다.

## 데이터와 동작

- 대시보드 자체에서도 인증 후에만 데이터를 읽는다. 사이트는 호스트에서 결정한다.
- 기존 결제·환불·정산 계산과 처리 API를 재사용한다.
- 일부 조회 실패는 확인 필요/실패로 표시하며, 성공한 다른 업무는 계속 보여준다.
- 방문 통계의 수집 이전 날짜/기록 누락을 0으로 연결하지 않는다. 기간 순방문자를 일별 합으로 바꾸지 않는다.
- 현재 주문 현황의 발주 전 주문은 paid/confirmed 상태의 합계다. 실제 발주 가능 여부는 기존 발주 화면에서 검증한다.
- 홈의 업무 항목은 중복 주문을 포함할 수 있으며, 우선 항목 6개와 유형별 총수를 먼저 보여준다.
- 홈의 매출·방문 기간 필터는 오늘 KPI나 전체 기간 업무 상태를 바꾸지 않는다. 범위가 각각 명시되어 있다.
- 주문·배송에서 서로 다른 처리 단계나 현재 목록에 없는 ID가 섞인 선택은 일괄 처리하지 않는다. 발주 검증, 요청 재시도 키, 출고 중지 확인, 송장 사전 검증, 환불 잔액 확인은 기존 처리 코드를 유지한다.
- 교환·반품은 기존 사이트 제한 API 2개를 함께 조회한다. 한쪽 실패 시 조회된 다른 신청과 실패 사유를 같이 표시한다. 신청 ID 딥링크도 두 조회에 유지한다.
- 상품 페이지는 직접 인증한 뒤 호스트 범위의 상품과 실판매량을 조회한다. 집계 실패/날짜 오류를 0으로 보이지 않는다. 사용 빈도 분석 없이 관리 기능이나 거래 이력을 삭제하지 않는다.

- 정산 페이지는 자체 인증 후 사이트 범위의 내역을 읽고 화면에 필요한 필드만 전달한다. 결제 키 등 메타데이터를 넘기지 않는다. 한국시간 기간/환불 반영 계산은 기존 로직을 그대로 사용한다. 환불 미확인 기간의 합계·수수료는 확인 필요로 표시한다.
- 회원 계정/역할은 두 스토어 공통, 구매 이력은 현재 스토어 기준임을 표시한다. 회원 목록 500명, 리뷰 300건 조회 한도도 표시한다. 회원 이력을 빠르게 전환해도 이전 응답이 다른 회원에게 표시되지 않는다.
- 조회 오류는 빈 목록과 구분하며 재조회는 읽기만 재시도한다. 회원/리뷰/예약의 반복 처리 클릭을 막고, 예약 변경 후 목록은 서버 응답으로 갱신한다. 문자 부분 실패 후 미발송 건수를 다시 조회한다.
- 숙박 명단은 페이지와 무관하게 검색 결과 전체를 내보낸다. 기존 문자 일괄발송은 숙소/검색 필터와 무관한 미발송 전체 대상임을 명시하고 확인 절차를 유지한다. 실제 문자를 보내는 검증은 실행하지 않는다.
- 예약 변경의 재고/차액/환불 API는 유지하며, 미리보기 응답의 위약금도 화면에 전달한다. 이전 날짜의 느린 재고 응답을 무시하고 차액 계산 중에는 입력을 잠근다.

## 검증과 검토

- `npm run test:admin-integrity`: 주문·취소·배송·환불·정산·인증 회귀 검사 통과.
- `npm run test:admin-charts`: 차트/메뉴 및 신규 통합 화면 검사 통과.
- TypeScript와 Next production build 통과. GitHub PR CI도 배포 전에 확인한다.
- 미리보기는 실제 운영 홈/메뉴/주문/배송반품/상품/정산/회원/리뷰/숙박예약 컴포넌트를 묶는다. 예시 데이터만 사용하는 로컬 응답으로 목록을 탐색할 수 있다. 실제 발주·송장 등록·취소·환불·저장 요청, 외부 네트워크 연결과 폼 전송은 막는다.
- 추가 검증: `tests/admin-list-workspace.cjs`에서 혼합·오래된 선택 차단, 송장 검색/번호 보존, KST 주문시각, 사이트별 목록, 상품 상태/기간, 교환·반품 부분 조회 실패와 신청별 버튼 구분을 확인한다. 기존 실판매량/송장/재고·환불 회귀 검사도 실행한다.
- 추가 화면 검증: 인라인 회원 승인·실패 후 stale 버튼 제거·회원 이력 응답 경합, 리뷰 필터와 중복 처리 차단, 예약 필터/명단 전체 내보내기/문자 부분 실패 잔여 건수, 정산 200건 이후 페이지·검색·KST·미확정 값·인증과 표시 필드 제한을 검사한다. 미리보기는 패키징 때 Node 전역 없는 환경에서 초기 실행 검사를 통과해야 생성된다.
- 생성: `node scripts/commerce-preview/build.cjs`, Next 빌드 CSS가 있는 상태에서 `node scripts/commerce-preview/package.cjs <absolute-output.html>`.
- 현재 환경에 지원되는 브라우저 제어 스킬이 없어 실제 관리자 브라우저 화면/반응형 시각 검증은 수행하지 않았다. 미리보기 검토가 필요하다.

관리자 메뉴·업무 동선이 바뀌는 개편이므로 기존 사용자 방침에 따라 구현과 검증 후 운영 반영 승인을 받는다. 승인 전 main 병합/운영 배포를 실행하지 않는다.
