# 배송관리 한 페이지 흐름

상태: 추가 검증에서 발견한 3건 수정 및 최종 검증 완료, 운영 배포 전. 최종 결과는 `docs/shipping-flow-validation-20260909.md` 참고.

## 화면
- `/admin/shipments`: 발주 대기 → 배송준비 → 배송중 → 배송완료를 동시에 표시. 상단 단계별 건수는 해당 영역으로 이동하는 링크.
- 취소·교환·반품 요청도 같은 페이지에서 처리. 기존 `tab`/`requestId` 링크는 해당 신청 영역으로 이동.
- 발주 확정 이력·엑셀 재다운로드 유지. 완료된 취소·교환·반품은 하단 이력으로 정리.

## 자동 처리
- 사이트별 주문 현황을 한 번 조회하여 화면 영역들이 공유. 화면이 보일 때 60초마다 갱신하고 처리 직후 재조회. 조회 중복 방지 및 변경 완료 후 재조회 보장.
- 주문 정보 이상·송장 누락·환불 보류·출고 예정일 경과/미지정 자동 분류. 예정일은 한국 날짜 기준으로 비교하고 미래 예약 출고를 지연으로 분류하지 않음.
- 송장 엑셀 열 위치 자동 인식. 헤더 없는 기존 순서도 지원. 누락·중복 주문번호·손상된 송장번호·알 수 없는 택배사는 등록 전 차단.
- 통합 화면의 송장 업로드는 발주 확정된 배송준비/배송중 주문인지 사전 확인.
- 송장 등록 성공/실패 및 문자 실패 표시를 갱신 후에도 보존. 실패 행만 파일 재시도 대상으로 유지. 네트워크 실패 시 입력 보존 및 작업 버튼 복구.
- 기존 배송 추적 스케줄(한국시간 07:30/19:30) 유지. 화면 자동 갱신은 조회만 하며 추적 API를 분마다 호출하지 않음.

## 수동 처리
- 발주 확정은 주문 선택·확인 후 기존 원자적/멱등 API 실행. 기존 공급사별 엑셀 생성 재사용.
- 공급사 발주서 전달과 송장 회신은 기존 방식으로 진행. 외부 공급사 연동 정보가 필요하며 자동 전송은 구현하지 않음.
- 취소·환불 및 수동 배송완료는 담당자 확인을 유지.

## 검증
- 전체 Next.js 빌드·TypeScript 통과.
- `node --test tests/shipping-flow.cjs tests/admin-workflow.cjs`: 19개 통과.
- 실제 React 컴포넌트에 격리 API 응답을 연결한 브라우저 검증: 전체 단계 동시 표시, 사이트 분리, 발주 확정 후 배송준비 이동, 열 순서가 다른 CSV 입력, 등록 실패 후 재시도, 성공/문자 실패 결과 유지, 배송중 이동, 배송조회 부분 실패 및 완료 이동, 조회 실패 시 마지막 현황 표시, 390px 화면 넘침 없음, 런타임 오류 없음.
- 운영 주문·결제·문자·공급사 전송 실행 없음. 미리보기 주문은 설명용.
