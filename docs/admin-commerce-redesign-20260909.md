# 관리자 업무 구조 개편 및 카카오 연결 계획

2026-09-09 · 로컬 검토본 · 배포/메시지 발송 없음

## 구현한 변경
- 업무 메뉴를 운영 홈, 상품, 주문·배송, 매출·정산, 고객, 공구, 설정·시스템의 7개 그룹으로 재구성.
- 접히는 메뉴, 사이트별 브라우저 즐겨찾기, 현재 위치와 관련 업무 바로가기. 산지픽 숙박 메뉴 제외 및 기존 서버 권한 유지.
- 공통 밝은 작업 화면과 표/입력 스타일. 각 업무의 기존 데이터·조회·처리 기능 유지.
- 상품 등록 5단계: 기본 → 가격/옵션/재고 → 배송/반품 → 전시/링크 → 최종 확인. 오류 항목 단계 이동 유지.
- 전체 주문의 주문번호를 누르면 모달 옆 패널로 상품·수령인·송장·배송조회 확인. 최신 상태 변경은 기존 상세 경로 사용.
- 운영 홈에 상품 등록, 주문 확인, 출고/송장, 결제 정산 바로가기.
- 고객 관리에 카카오 상담/알림 준비 화면 추가: 기존 채널 URL 확인, 공용 채널 여부, 6가지 문안 선택/복사와 발송 조건 안내.
- 앞서 검증한 송장 입력/배송완료 송장 보호/XLSX 번호 보존 수정 포함.
- 빌드를 막던 기존 categories GET의 선택적 Request 타입을 Next 경로 계약에 맞게 변경.

## 카카오 우선순위와 준비물
1. 상담 연결: 기존 사이트별 kakaoUrl 활용. 코드 기본값만으로 실제 채널의 소유권/상담 운영을 보장하지 않음. 산지픽 별도 주소가 없으면 공용 채널임을 표시.
2. 배송 시작 알림: 비즈니스 채널, 발송 서비스 계약/서버 인증정보, 승인된 배송 템플릿, 발신 프로필 준비. 송장 저장 후 발송 큐를 기록하고 결과 콜백/재시도를 구현.
3. 결제 완료/환불 결과/출고 일정 변경: 결제·환불·변경일 확정 이후만 이벤트 생성. API 성공 응답 이전 발송 금지.
4. 운영자 알림: 미출고/조회 실패/교환반품을 건수로 요약. 수신자 등록, 시간대·긴급도 설정 필요. 일반 카카오 메시지 API는 서비스 내 사용자간 전송용이므로 임의 관리자 전화번호 알림 수단으로 사용하지 않음. 발송 업체와 허용 용도 확인 후 수단 확정.
5. 재입고·공구 오픈: 고객 신청/동의/철회 기록과 광고성 메시지 분류 확인. 거래 안내용 알림톡에 임의로 홍보 문안을 섞지 않음.
6. 자주 묻는 질문: 출고 일정·배송비·교환반품 기준을 채널에 연결해 반복 문의 완화. 챗봇/상담톡 서비스 계약은 별도.

## 후속 발송 구현 계약
- 이벤트 키: site + order_id + event_type + event_version. 유니크 제약으로 중복 생성 방지.
- 상태: pending / sending / sent / failed / unknown. 응답 소실 unknown은 공급사 결과 조회 후 처리.
- DB 이벤트 기록은 주문 확정과 일관되게 처리. 공급사 요청은 주문 트랜잭션 밖에서 수행.
- 알림톡→문자 대체는 원 전송 실패 확정 후에만 시행. 공급사 자체 대체 발송과 앱 대체 발송을 중복 사용하지 않음.
- 운영자 링크는 관리자 인증, 고객 주문 링크는 주문 소유권 확인. 메시지에 주소/연락처/인증 토큰 노출 금지.
- 사이트별 채널/템플릿/발신 프로필/동의 분리. 공급사 및 템플릿 결정 전 자동 발송 스위치를 제공하지 않음.

## 검토 범위와 남은 작업
이번 구현은 관리자 구조/탐색/등록 단계/주문 요약/카카오 준비 화면이다. 카카오 발송 엔진·새 배송 템플릿 저장·표 전체의 열 크기 조절은 미구현이다. 기존 정산 계산, 주문 상태, 권한은 재설계하지 않았다.
미리보기의 등록/주문/배송/카카오 화면은 실제 클라이언트 컴포넌트를 사용한다. 홈·상품 목록·정산은 설명용 구성과 합성 데이터다. 미리보기는 외부 API 접근 및 실제 저장/발송을 막는다.
