# 산지픽 전시·비전시 링크 수정 검토본

기준 코드: main `f962dd3b90ff11d1eb9be0214fc575d613918805` 위의 `codex/sanji-link-periods`.
운영 배포·원격 푸시·운영 DB 변경은 실행하지 않았습니다. AI 트렌드 보류 작업은 포함하지 않았습니다.

## 상품 관리자 사용법

1. 산지픽 상품 수정 화면에서 **비전시 링크 사용**을 선택합니다.
2. **링크 시작·종료 일시**를 한국시간으로 입력합니다. 일반 판매 기간과 별도이며, 두 기간 조건이 모두 충족되어야 구매할 수 있습니다.
3. 옵션 없는 상품은 비전시 판매가를 입력합니다. 옵션 상품은 각 옵션의 전시 판매가 옆에 비전시 판매가를 직접 입력합니다.
4. 저장하면 저장한 기간의 링크 하나가 발급됩니다. 같은 기간에 다시 발급을 요청해도 같은 주소가 반환됩니다.
5. 상품 목록 또는 수정 화면에서 링크를 복사합니다. 특정 회원 제한은 없습니다.

| 옵션 예시 | 전시 판매가 | 비전시 판매가 | 비전시 링크 화면 |
|---|---:|---:|---|
| 사과 3kg | 14,900원 | 12,900원 | 12,900원에 구매 |
| 사과 5kg | 24,900원 | 21,900원 | 21,900원에 구매 |
| 선물 포장 | 별도 설정 | 미입력 | 해당 상품 옵션 제외 |

위 상품·가격은 사용법 설명용 예시입니다. 일괄 차액 계산은 제거했습니다. 비전시 옵션 가격을 비워도 전시 가격으로 대체하지 않습니다. 기존 추가상품(product_addons)은 별도 부가상품 가격 규칙을 유지합니다.

## 기간과 링크 동작

- 시작 시각 포함, 종료 시각 제외입니다.
- 시작 전·종료 후·해제·잘못된 코드에는 **잘못된 요청입니다** 화면을 표시합니다. 상품·가격·구매 버튼을 표시하지 않습니다.
- 열어 둔 산지픽 상품 화면도 종료 시각 이후 내용을 숨깁니다. 결제 승인 API도 서버에서 코드·기간·옵션·가격을 다시 확인합니다.
- 기간 변경은 현재 링크를 해제합니다. 겹치지 않는 새 기간을 저장하면 새 주소를 발급합니다. 같은 기간이나 과거 기간에 발급했던 주소는 재활성화하지 않습니다.
- 상품별 발급을 트랜잭션과 행 잠금으로 직렬화하고, 기간별 유일 제약을 둡니다.
- 발급 이력과 구매 이력은 삭제하지 않습니다. 링크 주소가 만료되어도 주문 조회와 환불 대조에 필요한 기록은 유지됩니다.
- **기존에 기간 없이 발급한 링크는 배포 후 유효하지 않습니다. 시작·종료와 옵션 가격을 설정하고 새로 발급해야 합니다.** 기존 비전시 옵션 가격을 자동 추정하거나 전환하지 않습니다.

## 주문 및 집계

- 서버에서 확인한 링크 코드, 시작·종료, 상품명, 옵션 ID·옵션명, 실제 단가를 주문 당시 값으로 저장합니다.
- 전시·비전시 구분은 주문에 저장한 링크 코드로 결정합니다. 인플루언서 귀속과 독립적입니다.
- 일반 구매와 비전시 구매, 서로 다른 비전시 링크 구매는 각각 나누어 결제합니다. 한 링크에서 여러 옵션을 함께 사는 것은 가능합니다.
- 판매 관리에 **구매 구분 필터**, **전시·비전시 판매 집계** 바로가기, 발주 엑셀에 **구매 구분·비전시 링크 코드** 열을 추가했습니다.
- 새 관리자 화면 경로: `/admin/link-sales`. 현재 로그인한 관리자 사이트 범위만 조회합니다.
- 한국시간 결제일 범위별로 결제 건수·최초 주문 수량·배송비 포함 총 결제액·확인된 환불액·순 결제액을 표시합니다.
- 환불은 환불일이 아니라 원래 주문이 속한 결제 기간·구매 구분에 반영합니다. 상품 삭제나 링크 만료 후에도 유지됩니다.
- 테스트 결제와 미결제는 집계에서 제외합니다. 과거 환불액 미기록이나 대조가 필요한 취소는 **환불 대조 필요**로 표시하고 순 결제액을 확정 표시하지 않습니다.
- 기존 환불 엔진이 ‘이미 환불됨’으로 복구한 건은 금액을 추정 기록하지 않고 대조 대상으로 표시합니다. PG 관리자에서 직접 처리한 과거 환불을 자동으로 소급 수집하는 기능은 포함하지 않았습니다.

## 검증 및 적용 준비

- `npm run test:secret-links`: PostgreSQL 호환 격리 DB와 결제 응답 모의 처리로 16개 검증.
- `node --test tests/admin-auth.cjs tests/today-work.cjs`: 기존 관리자 권한·오늘 처리할 일 24개 검증.
- `npm run build`: 운영 DB·결제 키 없이 빌드 검증. 기존 정적 페이지의 DB 조회는 격리된 미접속 주소를 사용하므로 조회 경고가 기록될 수 있습니다.
- 실제 결제·환불·고객 문자·운영 상품 변경은 실행하지 않습니다. 실제 관리자 브라우저 조작까지 확인한 것은 아닙니다.
- 새 마이그레이션 `scripts/secret-link-periods.sql`을 기존 `scripts/migrate-order-site.cjs`의 배포 트랜잭션에 연결했습니다. 재실행 검증을 포함합니다.
- 배포할 때에는 최신 main에 변경 범위를 합친 뒤, 기존 배포 절차로 DB 마이그레이션과 빌드를 적용해야 합니다. main 푸시는 자동 배포를 시작하므로 이번 검토에서는 실행하지 않았습니다.
