# 고객 편의·신뢰 기능과 외부 API 연결

블랜드픽과 산지픽에 같은 기능을 제공하되, 고객 데이터와 채널 설정은 사이트별로 분리한다. 실제 외부 서비스 가입·계약·승인이나 운영 발송 테스트를 대신하지 않는다. 개발 테스트는 격리 DB와 공급자 응답 모형만 사용한다.

## 반영한 기능

| 기능 | 고객 화면 | 운영 화면·처리 |
| --- | --- | --- |
| 관심 상품, 옵션별 재입고·공구 오픈 신청 | 공개 상품 상세, `/my-shopping` | 90일 유효, 해당 상품이 실제 구매 가능해지면 1회 알림. 사이트 알림 기본, 알림톡은 별도 선택·휴대폰 인증 필요 |
| 주문·환불·출고 일정 알림 | `/my-shopping`, 기존 주문 내역 | 결제 확정·환불 완료를 확인한 뒤 생성. `/admin/customer-care`에서 상태 확인 |
| 출고 예정일 변경 | 회원·비회원 주문 조회에 새 날짜와 사유 표시 | 주문 관리의 ‘출고 일정 안내’ → 새 날짜·사유 저장. 이전 일정 알림은 발송 직전 제외 |
| 문의·상품 Q&A | `/support`, 상품 상세 | `/admin/customer-care`에서 답변. 고객 공개 동의와 판매자 확인을 모두 거친 상품 문의만 공개. 주문 문의는 비공개 |
| 배송지 주소록 | 장바구니 결제, `/my-shopping` | 계정·사이트별 최대 10개. 선택 후 기존 배송비 계산 재실행 |
| 다시 구매 | 회원 주문 내역 | 현재 가격·판매 상태·옵션·재고를 재검증하고 가격 확인 후 장바구니 추가. 재요청 중복 방지. 추가 상품을 포함한 주문은 상품 화면에서 재선택 안내 |
| 상품 찾기·후기 | 상품 검색 제안, 재고·가격 필터, 가격 정렬, 후기 사진·평점 필터 | 공개 상품만 대상. 후기는 현재 불러온 후기 목록 안에서 정렬·필터 |
| 판매자 후기 답변 | 두 브랜드 상품 상세 | 리뷰 관리에서 답변 작성 |
| 식품·품질 안내 | 입력된 생산자·보관법·소비기한·주의 성분·품질 접수·반품 비용·인증 범위 표시 | 기존 상품 수정의 ‘상품·품질 안내’에서 별도 저장. 신규 상품은 먼저 생성 후 수정 |

기존 비밀 링크 구매, 기본 결제, 배송 SMS, 반품 완료 SMS 흐름을 유지한다. 반품 완료 건은 기존 SMS가 있으므로 새 환불 알림 대상에서 제외한다.

## 배포 순서

1. 기존 마이그레이션에 이어 `node scripts/prepare-customer-convenience.cjs`를 실행한다. `SHOP_DATABASE_URL`이 필요하며 반복 실행해도 데이터와 도입 시점을 보존한다.
2. 프로덕션 빌드 후 앱을 재시작한다. `deploy.yml`에 위 순서가 연결되어 있다. 새 테이블을 조회하므로 코드만 먼저 배포하면 안 된다.
3. 기존 알림 워크플로가 매시 7분·37분에 배송 알림과 `node scripts/process-customer-notifications.cjs`를 실행한다. GitHub 예약 실행 지연이 가능하며 실시간 발송을 보장하지 않는다.
4. 아래 환경변수를 설정하고 해당 브랜드의 승인·계약 정보를 확인한 뒤 외부 기능을 켠다. 빈 설정은 고객에게 활성 기능처럼 표시하지 않는다.

도입 이전 주문을 일괄 발송하지 않는다. 신규 주문·환불 검색 범위는 도입 시점 이후이면서 최근 24시간이다. 작업이 24시간 이상 중단된 구간은 자동 소급 발송하지 않으며 운영자가 주문·환불 이력을 대조해야 한다.

## 필요한 외부 설정

실제 Secret은 서버 환경변수에만 등록한다. Git, 문의 본문, 클라이언트 코드에 저장하지 않는다. 설정 예시는 `.env.example` 참조.

### SOLAPI 알림톡

- 기존 `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`을 재사용할 수 있다.
- `COMMERCE_ALIMTALK_ENABLED=true`일 때만 알림톡 발송을 허용한다.
- 브랜드별 `BLENDPICK_SOLAPI_PFID`, `SANJIPICK_SOLAPI_PFID`와 승인 템플릿 ID가 필요하다.
- `${BRAND}_ALIMTALK_${KIND}_TEMPLATE`의 BRAND는 `BLENDPICK`/`SANJIPICK`, KIND는 `PAID`, `SHIPPING`, `REFUND`, `DELAY`, `RESTOCK`, `OPENING`이다.
- 문의 답변은 사이트 내 알림이다. 답변 알림톡은 이번 구현 대상이 아니다.
- 기본 `COMMERCE_SMS_FALLBACK=false`. SMS 대체 발송을 사용하려면 명시적으로 `true`로 바꾸고 기존 `SOLAPI_SENDER`를 설정한다. 새 발송을 앱이 별도로 재시도하지 않고 공급자의 대체 발송 기능을 사용한다.
- 재입고·오픈 문안의 사용 가능 여부는 실제 카카오 템플릿 심사 결과에 따른다. 승인 전에는 해당 템플릿 환경변수를 설정하지 않는다. 홍보·프로모션 문구를 섞지 않는다.

| KIND | 승인 템플릿 변수 |
| --- | --- |
| PAID | `#{주문번호}`, `#{결제금액}`, `#{출고예정일}`, `#{주문조회URL}` |
| SHIPPING | `#{주문번호}`, `#{상품명}`, `#{택배사}`, `#{운송장번호}`, `#{주문조회URL}` |
| REFUND | `#{주문번호}`, `#{환불금액}`, `#{주문조회URL}` |
| DELAY | `#{주문번호}`, `#{출고예정일}`, `#{안내사유}`, `#{주문조회URL}` |
| RESTOCK, OPENING | `#{상품명}`, `#{상품URL}` |

문안 초안은 `/admin/notifications`에 있다. 브랜드명은 각 채널의 승인 문안에 맞춘다. 링크 변수에는 두 브랜드의 정식 HTTPS 도메인을 사용한다.

### 채널톡

- 브랜드별 `${BRAND}_CHANNEL_PLUGIN_KEY`, `${BRAND}_CHANNEL_MEMBER_HASH_SECRET`이 필요하다.
- Member Hash Secret은 채널톡이 발급한 64자리 hex 문자열이다. 서버에서 hex를 디코딩해 HMAC-SHA256을 계산한다. 채널톡 콘솔에서도 회원 인증을 활성화한다.
- 고객이 상담 버튼을 누른 경우에만 SDK를 로드한다. 로그인 회원 또는 주문자 휴대폰 인증을 완료한 비회원만 이용한다.
- 사이트별 회원 식별값과 **본인 소유로 검증한** 주문번호·상태만 전달한다. API Secret·주소·결제키·휴대폰을 프로필로 보내지 않는다.
- 연결 실패 시 오류와 기존 문의 접수 화면을 제공한다. 서버 설정과 별도로 채널톡 측 사용 요금·도메인 설정을 확인해야 한다.

### 식품안전나라 HACCP 조회

- `HACCP_SERVICE_KEY`: 식품안전나라에서 **I0580 (HACCP 인증업체)** 활용 신청을 완료한 인증키. 다른 공공데이터 서비스 키와 혼동하지 않는다.
- 관리자만 지정번호로 서버를 통해 조회한다. 조회 결과를 제조업체·품목·인증 범위·취소/반납 상태와 대조하고 상품 안내를 작성한다.
- API 응답만으로 상품 전체에 인증 배지를 붙이거나 품질을 보증하지 않는다. Secret이 포함된 URL·공급자 원문 오류는 고객 응답과 로그에 남기지 않는다.
- 실제 키로의 응답·할당량·네트워크 검증은 키 등록 후 필요하다.

### 토스 간편결제·카카오 동의 화면

- `${BRAND}_TOSS_EASY_PAY`: 현재 토스 가맹점에서 계약·활성화된 항목만 `TOSSPAY,NAVERPAY,KAKAOPAY` 중 지정한다. 빈 값이면 기존 결제창을 유지한다. 기존 토스 키를 재사용하며 이 설정만으로 새 결제 계약이 생기지 않는다.
- `${BRAND}_KAKAO_SYNC_TERMS`: 카카오 콘솔에서 이미 등록·승인된 서비스 약관 태그 목록을 쉼표로 지정할 수 있다. 로그인 인가 요청의 `service_terms`에 전달하는 옵션이다. 신규 카카오싱크 가입 승인이나 별도 마케팅 동의 저장·관리까지 구현한 것은 아니다. 필요한 약관이 등록되지 않았다면 비워 둔다.

## 발송 결과와 중복 방지

- 주문 ID, 환불 작업 키, 알림 신청 회차, 출고일 변경 회차별 고유 키로 알림을 한 번만 생성한다.
- `accepted`는 SOLAPI 접수, `delivered`는 조회된 성공 수신 결과다. 관리자 화면에서 구분한다.
- 네트워크 타임아웃·비JSON·불명확한 결과는 `review`로 보내 자동 재발송하지 않는다. 이미 공급자가 접수했을 수 있으므로 SOLAPI 발송 이력을 대조한다.
- 5분 이상 `sending`인 작업도 `review`로 전환한다. 서버 중단 후 무조건 다시 보내지 않는다.
- 설정 누락은 `blocked`. 설정 후 24시간 이내 대기 건만 관리자가 발송 재개할 수 있다. 오래된 알림·취소 주문·해지 신청·다시 품절된 상품·비공개/삭제/타 브랜드로 이동한 상품은 발송하지 않는다.
- 배송 알림은 기존 단일 `shipment_notifications` 큐를 사용한다. 알림톡 설정이 없으면 기존 SMS, 있으면 알림톡 경로로 한 번만 보낸다. 기존 배송 화면의 ‘접수 완료’는 수신 확정이 아니다.
- 휴대폰 수집·정리, 회원 탈퇴 정리, 문의 공개 조건을 처리한다. 주문 이벤트 키는 탈퇴 후에도 남겨 동일 주문 알림의 재생성을 막고, 문의 기록은 기존 3년 보유 정책에 따라 고객 계정 접근을 끊고 비공개로 보존한다.

## 검증

`npm run test:customer-convenience`는 격리 PostgreSQL 호환 DB의 권한·사이트 분리·옵션 재고·알림 중복·해지·출고일 변경·재구매 가격 및 수량 검증과 공급자 HMAC/응답·비JSON/네트워크 오류 처리를 검사한다. 실제 고객이나 외부 서비스에 메시지를 보내지 않는다.

기존 Admin integrity, 구매·계정, 매출·배송·환불·관리자 작업, 상품 SEO·산지픽 마이페이지 회귀 테스트와 `CI=true CI_DB_FREE_BUILD=true npm run build -- --webpack`으로 함께 확인한다. 운영 키를 이용한 실제 인증·결제·알림 수신 확인은 외부 설정 후 별도 실행이 필요하다.
