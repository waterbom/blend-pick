# 산지픽 전용 관리자와 결제 기록 분리

- 산지픽 관리자: `https://sanjipick.blendpunch.com/admin`
- Shop 관리자: `https://shop.blendpunch.com/admin`
- 기존 관리자 계정과 Toss 결제 승인·취소 연동을 재사용한다. PG 가맹점이나 입금 계좌를 별도로 만드는 변경은 아니다.
- 관리자 화면과 API는 요청 도메인으로 사이트를 결정한다. `site` 쿼리, `x-site` 헤더, 미리보기 쿠키로 다른 사이트의 기록을 조회할 수 없다.
- 주문, 배송, 반품·환불, 주문 리뷰, 회원 구매 이력, 매출·손익, 인플루언서 정산과 공구 비용을 사이트별로 분리한다. 상품·공구 설정, 회원 계정과 인플루언서 기본 정보는 기존 공유 구조를 유지한다.
- 다른 사이트 주문 ID로 상세 조회, 환불, 배송 또는 일괄 변경을 요청하면 거부한다. 산지픽에서는 호텔 예약 메뉴와 관련 관리자 API를 제공하지 않는다.
- 신규 산지픽 일반·장바구니·공구 주문번호는 `SJ-`, Shop은 `BP-`를 사용한다. 결제 승인 요청과 인증키는 기존 방식을 유지한다.
- 추가 결제 링크에 사이트를 서명해 넣고 해당 사이트에서만 결제할 수 있게 한다. 사이트 정보가 없는 기존 링크는 Shop으로 처리한다.
- `scripts/migrate-order-site.cjs`가 배포 전에 `scripts/admin-site.sql`을 트랜잭션으로 실행한다. 공구 비용·지급 정산에 사이트를 추가하고 지급 정산 고유키를 `(site, campaign_id, influencer_id)`로 변경한다. 재실행할 수 있으며 기존 데이터는 보존한다.
- 과거 사이트 미분류 데이터는 기존 Shop 귀속을 유지한다. 상품명이나 카테고리만으로 과거 결제를 산지픽으로 임의 이동하지 않는다.

## 검증

운영 DB, 실제 결제, 문자 발송 없이 독립 PostgreSQL(PGlite)에서 검증한다.

```sh
npm install --prefix /tmp/blendpick-admin-test --ignore-scripts @electric-sql/pglite@0.3.14
PGLITE_MODULE=/tmp/blendpick-admin-test/node_modules/@electric-sql/pglite node tests/admin-site.cjs
node tests/sanjipick-mypage.cjs
npm run build
```

관리자 테스트는 마이그레이션 반복 실행, 도메인별 조회·수정 차단, 정산·손익 계산, 양 사이트의 기존 결제 승인과 저장 경로를 포함한다. Toss HTTP는 모의 응답으로 검증하므로 실결제 테스트를 의미하지 않는다.

## 작업 완료 브리핑

사용자 요청에 따라 앞으로 작업 완료 시 변경·추가·삭제한 내용과 검증·배포 결과를 학습노트 형식으로 6~10줄로 간단히 보고한다.

## 관리자 인증과 계정 전환 수정

- 원인: 기존 개인 이메일·카카오 로그인과 일반 로그아웃은 `admin_token`을 삭제하지 않았다. Header는 이 토큰을 먼저 읽어 개인 마이페이지에서도 이전 관리자 세션을 표시할 수 있었다.
- 개인 로그인·카카오 로그인·일반 로그아웃 시 관리자 쿠키를 삭제한다. 관리자 로그인 시 일반 회원 쿠키도 삭제한다.
- `lib/auth.ts`의 관리자 토큰 발급·검증은 `admin@blendpick.com`만 허용한다. 관리자 레이아웃의 일반 회원 토큰 대체 인증 경로를 제거한다.
- 관리자 인증에 사용하던 공개된 기본 서명 키를 제거한다. 배포 환경에 별도의 `ADMIN_JWT_SECRET`이 없거나 기존 공개 기본값이면 관리자 로그인을 503으로 중단하고 기존 토큰도 거부한다. 배포 전에 이 환경변수 설정을 확인해야 한다.
- 일반 회원의 role 값은 관리자 권한의 근거로 사용하지 않는다. 운영 DB의 전체 계정 목록을 조회하거나 역할을 변경한 작업은 아니다.
- `node tests/admin-auth.cjs`: 실제 JWT 서명 검증과 모의 DB를 사용한 12개 검사. 이전 관리자 표시 재현, 이메일·카카오 계정 전환, 양쪽 로그아웃 쿠키 제거, 다른 이메일 관리자 토큰·일반 토큰·만료 토큰 거부를 검증한다.

- 배포는 관리자 서명 키 설정을 값 노출 없이 먼저 확인한다. 키 검사·의존성 설치·빌드가 실패하면 서버를 재시작하지 않는다.

## 관리자 마이페이지 로그인 반복 수정

관리자 로그인 API는 `isAdmin: true`와 `/admin` 목적지를 반환한다. 로그인 화면은 관리자 응답이면 이전 고객용 redirect보다 `/admin`을 우선한다. Shop·산지픽 마이페이지도 유효한 관리자 토큰을 먼저 확인해 같은 호스트의 `/admin`으로 이동한다. 관리자 계정에 일반 회원 계정이나 고객용 토큰을 추가하지 않는다. 인증 테스트 13개와 마이페이지 회귀 검사 21개를 통과했다.

## 장바구니와 카카오 복귀 경로 분리

- `scripts/storefront-site.sql`을 기존 배포 마이그레이션 트랜잭션에 추가했다. cart.site와 사이트별 고유키를 추가하며 기존 장바구니 항목은 Shop으로 보존한다. 새 산지픽 장바구니는 별도 항목으로 저장한다.
- 장바구니 API는 사이트·회원 소속으로 조회·수정·삭제한다. 옵션 없는 상품은 트랜잭션 잠금으로 같은 사이트 안에서 수량을 합친다. 결제 승인 전에 기존 장바구니 항목의 사이트·회원을 확인하고, 승인 후에도 해당 사이트·회원 항목만 정리한다.
- 운영 Shop의 `/sanji/*`는 정식 산지픽 도메인으로 이동한다. 운영에서 미리보기 쿠키는 결제 사이트를 바꾸지 않는다. 개발 환경 미리보기만 유지한다.
- 카카오 시작 시 목적 사이트·복귀 경로를 DB에 저장하고 10분짜리 일회성 state를 발급한다. 일회성 검증 쿠키만 `.blendpunch.com`에 공유한다. 기존 `KAKAO_REDIRECT_URI` 설정은 그대로 유지한다.
- 등록된 Shop 콜백에서 산지픽 로그인이 완료되면 세션 토큰을 URL에 넣지 않고, 60초짜리 일회성 교환 코드로 산지픽 `/api/auth/kakao/complete`에 전달한다. 시작 브라우저 검증값과 사이트를 확인하고 산지픽 호스트 전용 세션을 발급한다. 교환 코드의 재사용·만료·다른 사이트 사용은 거부한다.
- Shop에서 시작한 카카오 로그인은 Shop에 머무른다. 로그인 오류도 확인된 원래 사이트로 돌려보낸다. 회원 계정 DB·토스 가맹점은 공유하며 사이트별 로그인 세션과 장바구니·주문 기록은 분리한다.
- `tests/storefront-site.cjs`의 11개 검사로 실제 PostgreSQL SQL과 모의 카카오 응답을 검증한다. 기존 인증 13개·마이페이지 21개·관리자 및 결제 27개 검사도 수행한다. 실제 카카오 계정 로그인과 실결제는 자동 테스트에 포함하지 않는다.

```sh
PGLITE_MODULE=/tmp/blendpick-admin-test/node_modules/@electric-sql/pglite node tests/storefront-site.cjs
```

## 어드민 화면 분리 (다른 사이트처럼)

- 사이드바: 산지픽은 딥그린 팔레트 + 산지픽 로고, "산지 직송 / 후기 관리" 표기. Shop은 기존 다크 무채색 (`components/admin/AdminSidebar.tsx` THEME). 배경색도 사이트별.
- 상품 관리·상품 목록 API·카테고리 API는 접속 도메인으로 걸러진다 (`lib/admin-site.ts adminProductScopeSql`): 산지픽 어드민은 `산지픽 농산물`/`산지픽 해산물` 카테고리 상품만, Shop 어드민은 그 외만. 상품 테이블 자체는 공유.
- 산지픽 어드민에서 상품 등록 시 카테고리는 산지픽 카테고리만 보이고, 다른 값이면 `산지픽 농산물`로 저장한다.

## 결제 금액 서버 검증 (승인 전 차단)

- `lib/order-amount.ts`: 단품(`verifySingleAmount`)·장바구니(`verifyCartAmount`) 결제 확정 API가 토스 승인 **전에** 상품가·옵션가·추가옵션·배송비를 DB 기준으로 다시 계산해, 화면이 보낸 `totalAmount`/`shippingCost`/`amount`와 하나라도 다르면 400으로 막는다 (승인 전이라 카드 청구 없음).
- 계산은 화면과 같은 함수(`lib/shop-price.ts shopUnitPrice`, `lib/shipping.ts cartShippingFee`)를 쓴다. 가격이 결제 도중 바뀐 경우도 같은 메시지("결제 금액이 현재 상품 가격과 달라요")로 막히며, 서버 로그에 불일치 상세가 남는다.
- 검증 시나리오 10개(옵션·조건부 무료·건별 배송비·추가옵션·금액 조작·없는 상품)는 가짜 DB로 확인했다. 호텔·공구(campaign) 결제는 대상이 아니다.

## 전시/비전시 판매 + 비밀링크(링크가격)

- `scripts/secret-link.sql`(배포 마이그레이션 트랜잭션에 포함): `products_shop.is_visible`(기본 true), `link_price`, `link_code`(부분 유니크), `orders.link_code` 추가. 기존 상품은 전부 전시 상태로 유지된다.
- 전시 판매 상품: 메인·카테고리·검색·상품목록·사이트맵에 노출. 비전시 판매 상품: 그 어디에도 노출되지 않지만 상세 URL·비밀링크로 들어오면 결제·주문·재고 차감이 일반 상품과 똑같이 동작한다. 비전시 상세 페이지는 검색엔진 색인에서 제외(noindex)한다.
- 목록 제외 조건은 `lib/sale-window.ts`의 `VISIBLE_SQL`로 통일: Shop 메인·/products·오픈 예정 플로팅·사이트맵, 산지픽 메인·검색·"함께 본 상품"·메인 후기가 모두 같은 조건을 쓴다.
- 링크가격: 상품 수정의 '전시 · 비밀링크' 섹션에서 전시가(판매가)와 별도로 입력한다. 산지픽 상품은 같은 섹션에서 비밀링크(`https://sanjipick.blendpunch.com/p/<id>?k=<코드>`)를 발급·재발급·해제한다(`POST/DELETE /api/admin/products/[id]/secret-link`, 접속 도메인 범위의 상품만). 코드는 16자 난수이며 화면(클라이언트)에는 내려보내지 않는다.
- 가격 규칙(`lib/secret-link.ts`): 코드가 상품의 `link_code`와 맞고 `link_price`가 있을 때만 적용. 옵션 없는 상품은 링크가 그대로, 옵션 상품은 옵션가마다 `(링크가 − 전시가)` 차액을 똑같이 더한다. 판매 페이지 표시·결제 화면·승인 전 금액 검증(`lib/order-amount.ts`)이 전부 이 함수를 쓴다.
- 결제 흐름: 산지픽 판매 페이지 → 단품은 `/products/<id>/checkout?k=`, 옵션은 `cartCheckoutData.items[].link_code` → 결제 확정 API가 DB 기준으로 링크가를 다시 계산해 일치할 때만 승인하고 `orders.link_code`에 스냅샷을 남긴다. 틀린 코드는 조용히 전시가로 계산되므로 화면 금액을 조작해도 승인되지 않는다.
- 어드민 판매 관리 목록은 비밀링크 결제 주문에 '🔗 비밀링크' 표시, 상품 관리 목록은 '비전시' 탭·배지와 링크가를 보여준다.
